**CLI build contexts honour `.dockerignore`** — `image build --context DIR`
uploads what `docker build` (BuildKit) uploads for the same ignore file, and
the 64 MiB limit counts only what is uploaded. `<Dockerfile>.dockerignore`
next to the Dockerfile takes precedence over the root `.dockerignore`. The
ignore file is read as Docker reads it, and a pattern that matched a
directory applies to its contents, so `!config` after `**/*.pem` re-includes
`config/` but not `config/server.pem`. An excluded directory is walked only
when a `!` pattern could re-include something inside it, an unreadable
excluded directory no longer fails the build, and, as with `docker build`, a
pattern with a syntax error (`[a-`) fails the build up front while one that
cannot be compiled into a matcher (`foo\q`) fails it only when a path
reaches it. The Dockerfile and the ignore
file are always uploaded, also when their names contain pattern characters.
A tar context is sent as is; `sandbox cp` is unchanged.
