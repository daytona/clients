**Daytona SDKs and CLI 2.x** — the first public release of the 2.x Python and TypeScript SDKs and the Go `daytona` CLI. Highlights:
- **Versioned clients:** one root client with `.v2` (the new API) and `.v0` (the previous 0.x SDK, pinned and bundled, so existing code keeps working with a small import change). Python ships both `Daytona` (blocking) and `AsyncDaytona` (async-native). Reading or assigning a 0.x member on the root client raises an error that points at `.v0`.
- **Sandboxes:** one create method per source: `create()` from an image (or none at all, to boot a platform image), `create_from_snapshot` / `createFromSnapshot`, `create_from_build` / `createFromBuild` for an inline Dockerfile, and `create_macos` / `createMacos`. Each takes an optional per-call `region` and an `idempotency_key` / `idempotencyKey`, and waits for the sandbox with a seconds budget, returning the handle however the wait ends. Add `fork()` (memory or disk-only), lifecycle methods that wait for their state, lifecycle policies (timeout and idle-timeout pairs, `reset_idle_timer()`), one-page `list()`, `search()` with filters, system metrics, labels, and a serializable `SandboxHandleJSON`. CPU is expressed in cores (1 core = 2 vCPUs). One `resources` entry takes a request and a limit, `disk_max` included.
- **macOS sandboxes:** `create_macos` / `createMacos` and `daytona sandbox create-macos`, with sizes, disk, secrets, volumes, network policy, persistence, fork and snapshots. Dedicated Macs are reserved through `reservations` (single, bulk, renew, auto-renew) and `daytona reservation`. Find the regions that serve Macs with `GET /regions`, and the models, availability and prices with `mac_models.catalog()` / `macModels.catalog()` or `daytona mac-model list --region R`.
- **Regions:** `GET /regions` is the single region list. It's flat, each region names the broader regions it's inside, and it reports `default_region_id`. The global region is `earth`.
- **Toolbox:** files (bulk read and write, depth-aware listing, search and replace, watch handles, streaming and atomic transfers), git (clone, pull, push, remotes, reset, restore and more, with finite default deadlines), processes (argv or shell commands, persistent shell sessions), and computer use (desktop state, accessibility node values, typed failures). There's also Docker status.
- **Networking and access:** Linux and macOS `network_policy` with compare-and-swap updates, signed and revocable preview links with expiry, pre-signed file URLs minted by the API, short-lived per-sandbox access tokens that refresh on their own, and runtime-managed sandbox secrets with an explicit `allowed_domains` scope.
- **Images and snapshots:** build per architecture, pull with a readiness wait, stream resumable build logs, use `snapshots.get()` / `snapshots.delete()`, and register registries, including Amazon ECR by access key or IAM role.
- **Volumes:** a `volumes` service to create, get, list, iterate and delete shareable volumes; a `volumes` create option to mount them, including subpaths; and `sandbox.volumes.pull()` to refresh mounted data. The CLI includes the `volume` command group and `--volume` on sandbox creates, including `create-macos`.
- **Organization management:** API key introspection, audit log reads and ranges, organization limits and usage (resources, storage, image and snapshot sizes), project budgets, billing, invitations, service accounts, and import of archived Daytona v0 sandboxes.
- **Errors:** one error envelope (`code`, `message`, `source`, `trace_id`) across the API and toolbox, mapped to typed errors such as `LimitExceededError`, `SandboxTerminalStateError`, `ImageTooLargeError`, `MAC_DISK_FULL`, `SIGNUP_NOT_INVITED` and `USER_SUSPENDED`. Server-reported enum values the SDK doesn't know read as `'unknown'` instead of failing.
- **CLI:** one binary for sandbox lifecycle, `exec` / `ssh` / `cp`, processes and ports, images, snapshots, secrets, registries, members, invitations, audit, billing and regions. It connects to the Daytona API by default and supports browser, device and WorkOS login. `daytona version` reports the connected API's build.
